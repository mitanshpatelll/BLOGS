Learn the rules

01The 8 types and every typeof result

JavaScript has exactly eight types. Seven are primitives: undefined, null, boolean, number, bigint, string and symbol. The eighth is object, and arrays, functions, dates, maps and regexes are all objects underneath.

One idea before anything else: values have types, variables don't. let x = 1; x = "a"; is legal because the type lives on the value, not on the variable.

Trap

Why is typeof null equal to "object"? The first engine stored values with a small type tag, and objects had the tag 000. null was the NULL pointer, all zeros, so it read as an object. A fix was proposed years later and rejected because it would break too much of the web.

Check types the reliable way

value === null                                // null
Array.isArray(value)                          // array
typeof value === "object" && value !== null   // non-null object (misses functions)
Object.prototype.toString.call(value)         // "[object Array]", "[object Null]", "[object Date]", "[object Map]"

Object.prototype.toString reads the internal tag (or Symbol.toStringTag). It is the most reliable general-purpose type check in the language.

Symbols in one paragraph

Every Symbol() call creates a unique value, so Symbol("a") !== Symbol("a"). They make collision-free property keys and are hidden from for...in, Object.keys and JSON.stringify. Symbol.for("a") uses a global registry and returns the same symbol every time. Well-known symbols such as Symbol.iterator, Symbol.toPrimitive and Symbol.toStringTag let objects hook into language behaviour.

Autoboxing: why "abc".length works

Primitives have no properties. When you write "abc".length, the engine wraps the primitive in a temporary String object, looks the property up on String.prototype, then throws the wrapper away. That is why this happens:

const s = "abc";
s.foo = 1;   // sloppy mode: silently lost. strict mode: TypeError
s.foo;       // undefined

Number(x) without new is a conversion and returns a primitive. new Number(x) creates a wrapper object that is always truthy. Never use it. new Symbol() and new BigInt() throw a TypeError.

02Primitives vs references: pass by sharing

Primitives are immutable and compared by value. Objects are mutable and compared by identity, meaning whether two references point at the same object in memory.

"a" === "a"                          // true
({}) === ({})                        // false: two different objects
const a = {}; const b = a; a === b   // true: same reference

Assignment always copies the value. For an object, the value is a reference, so the reference is copied and the object is not.

Function arguments work the same way. Arguments are passed by value, and an object's value is its reference. This is called call by sharing.

function f(obj) {
  obj.x = 1;       // mutates the shared object: visible outside
  obj = { x: 2 };  // rebinds the local parameter only: NOT visible outside
}
const o = {};
f(o);
o.x;  // 1

Interview answer

"JavaScript is always pass by value. For objects, the value being passed is a reference, so mutations are shared but reassignment is not." That is why you can't write a swap(a, b) function that swaps the caller's variables.

Primitives can't be mutated

let s = "cat";
s[0] = "b";        // ignored (strict mode: TypeError)
s.toUpperCase();   // returns a NEW string; s is still "cat"

const is not immutability. It locks the binding, not the value: const o = {}; o.x = 1; is fine. Object.freeze is shallow, so nested objects stay mutable.

03Number internals: why 0.1 + 0.2 isn't 0.3

Every number is a 64-bit float

JavaScript has no separate integer type. Every number is an IEEE-754 double: 1 sign bit, 11 exponent bits and 52 fraction bits. An implicit leading 1 gives 53 bits of precision.

0.1 in binary repeats forever, the same way 1/3 is 0.333… in decimal, so it is stored rounded. Add two rounded values and you get 0.30000000000000004. Fix it by comparing with a tolerance, by working in integers (money in paise or cents), or by rounding only for display.

(1.005).toFixed(2)   // "1.00": 1.005 is really stored as 1.00499999…

Number.EPSILON is relative

Number.EPSILON is 2^-52, about 2.22e-16: the gap between 1 and the next representable double. That gap grows with the size of the number, so scale it for anything big:

Math.abs(a - b) <= Number.EPSILON * Math.max(Math.abs(a), Math.abs(b))

Safe integers and the 253 cliff

Number.MAX_SAFE_INTEGER is 2^53 - 1 = 9007199254740991. Above it, not every integer can be represented:

2**53 === 2**53 + 1          // true
Number.isSafeInteger(2**53)  // false

Real-world bug

A backend sends a 64-bit database ID as a JSON number. JSON.parse silently rounds it and your app requests the wrong record. Big IDs should travel as strings, which is why Twitter's API has an id_str field.

Number.MAX_VALUE is about 1.79e308; anything bigger becomes Infinity. And a classic trap: Number.MIN_VALUE (5e-324) is the smallest positive number, not the most negative one.

NaN: the value that isn't equal to itself

typeof NaN is "number". You get it from 0 / 0, Number("abc"), undefined + 1, Math.sqrt(-1) and Infinity - Infinity. It is the only value where x === x is false.

Number.isNaN(x)     // good: no coercion
Object.is(x, NaN)   // good
x !== x             // good: the old trick
isNaN(x)            // trap: coerces first, so isNaN("abc") is true and isNaN("") is false

The same split exists for isFinite and Number.isFinite: the global version coerces, the Number. version doesn't.

-0 is real

Floats have a sign bit, so -0 exists.

0 === -0             // true
Object.is(0, -0)     // false
1 / -0               // -Infinity: one way to detect it
Math.round(-0.4)     // -0
0 * -1               // -0
String(-0)           // "0": hides it
JSON.stringify(-0)   // "0"

It is useful when the sign of a value that reached zero still matters, such as the direction of a gesture or an animation's velocity.

Bitwise operators work on 32-bit integers

x | 0 and ~~x truncate to a 32-bit signed integer, so 2**31 | 0 is -2147483648. Don't use them on large numbers.

parseInt vs Number

Number("12px")        // NaN: the whole string must be numeric
parseInt("12px")      // 12: parses until the first invalid character
Number("")            // 0   (trap)
parseInt("")          // NaN
parseInt(0.0000005)   // 5: String(5e-7) is "5e-7", which parses as "5"

["1", "2", "3"].map(parseInt)   // [1, NaN, NaN]
// map calls parseInt(value, index):
// parseInt("2", 1) is NaN because radix 1 is invalid
// parseInt("3", 2) is NaN because "3" is not a binary digit

Always pass the radix: parseInt(s, 10).

BigInt

Arbitrary-precision integers, written 10n or BigInt(10). Use them for 64-bit IDs, cryptography and nanosecond timestamps.

1n + 1               // TypeError: no implicit mixing with Number
1n + BigInt(1)       // 2n
5n / 2n              // 2n (truncates)
+1n                  // TypeError: unary + would lose precision
Number(10n)          // 10 (explicit conversion is fine)
BigInt(1.5)          // RangeError
1n == 1              // true
1n === 1             // false: different types
1n < 2               // true: comparisons across types are allowed
JSON.stringify(1n)   // TypeError
Math.max(1n)         // TypeError: Math doesn't support BigInt

04The four abstract operations behind every coercion

The spec defines a handful of internal algorithms, and every implicit conversion runs through them. Learn these four and any coercion puzzle becomes mechanical.

ToPrimitive(input, hint)

Converts an object to a primitive. The hint is "string", "number" or "default".

  1. If the object has a [Symbol.toPrimitive] method, call it with the hint. It must return a primitive, or a TypeError is thrown.
  2. Otherwise run OrdinaryToPrimitive. With hint "string", try toString() then valueOf(). With "number" or "default", try valueOf() then toString().
  3. The first method that returns a primitive wins. If neither does, a TypeError is thrown.
Which hint is used where
ContextHint
String(obj), `${obj}`, property key o[obj]"string"
Number(obj), +obj, -, *, /, <, >"number"
Binary +, == against a primitive"default"

A plain object's valueOf() returns the object itself, which isn't a primitive, so it falls through to toString() and gives "[object Object]". An array's toString() is join(",").

The Date exception

Date treats the "default" hint as "string", so new Date(0) + 1 concatenates text while new Date(0) - 1 gives -1.

ToBoolean

A pure lookup: no ToPrimitive, no method calls. The eight falsy values become false and everything else becomes true. Every object is truthy, including an empty array and new Boolean(false).

05The 8 falsy values

Memorise this list. Everything not on it is truthy.

  • false
  • 0
  • -0
  • 0n
  • ""
  • null
  • undefined
  • NaN

There is a ninth, exotic one: document.all, a legacy browser object that is deliberately falsy. Trivia only.

Truthy values that surprise people:

  • "0"
  • "false"
  • " "
  • []

  • function () {}
  • new Boolean(false)
  • -1
  • Infinity

&& and || return an operand, not a boolean

"a" || "b"   // "a"
0 || "b"     // "b"
"a" && "b"   // "b"
0 && "b"     // 0

|| vs ??

const limit = count || 10;   // bug: when count is 0, limit becomes 10
const limit = count ?? 10;   // only null and undefined fall back

React Native crash

When the list is empty, the left side evaluates to 0 and React Native tries to render it outside a <Text> component.

{items.length && <List />}
// length 0 → renders 0 → "Text strings must be rendered within a <Text> component"

{items.length > 0 && <List />}   // safe

06== vs === vs Object.is vs SameValueZero

=== strict equality

Different types give false. Same types are compared directly, with two number quirks: NaN !== NaN and +0 === -0. Objects compare by reference.

The == algorithm (know it cold)

For x == y, the spec's IsLooselyEqual runs these steps:

  1. Same type: use ===.
  2. null == undefined is true. Those two loosely equal only each other and themselves.
  3. Number vs String: convert the string with ToNumber, then compare.
  4. BigInt vs String: convert the string to a BigInt. An invalid string gives false.
  5. Boolean vs anything: convert the boolean to a number first, then start again.
  6. Object vs primitive: run ToPrimitive on the object with hint "default", then start again.
  7. BigInt vs Number: compare the mathematical values.
  8. Anything else is false.

Rule 5 causes most of the traps:

"true" == true   // false: true → 1, "true" → NaN, and NaN == 1 is false
"1" == true      // true:  true → 1, "1" → 1

Walkthrough: [] == ![]

![]            → false        [] is truthy, so its negation is false
[] == false    → [] == 0      rule 5: the boolean becomes a number
[] == 0        → "" == 0      rule 6: ToPrimitive([]) is ""
"" == 0        → 0 == 0       rule 3: ToNumber("") is 0
               → true
null == 0            // false: rule 2, null only equals undefined
null == false        // false: false → 0, then null == 0 is false
undefined == 0       // false
[0] == false         // true:  false → 0, [0] → "0" → 0
if ([0]) {}          // runs! Truthiness and == are different questions
[1, 2, 3] == "1,2,3" // true
NaN == NaN           // false

Relational operators play by different rules

<, >, <= and >= run ToPrimitive with hint "number" on both sides. If both results are strings they compare character codes; otherwise both sides go through ToNumber.

null >= 0        // true:  null → 0, and 0 >= 0
null > 0         // false
null == 0        // false: == has the special null rule; relational operators don't
"10" < "9"       // true:  both strings, so "1" < "9"
"10" < 9         // false: numeric comparison
undefined >= 0   // false: undefined → NaN, and every NaN comparison is false

Object.is (SameValue)

Identical to === except for two cases: Object.is(NaN, NaN) is true and Object.is(0, -0) is false.

Why React developers care

React uses Object.is for the useState bail-out, for useEffect and useMemo dependencies, and for React.memo's shallow compare. Setting state to the same object skips the re-render; setting it to {...obj} creates a new reference and re-renders.

SameValueZero

Like Object.is, except +0 and -0 are equal. Array.prototype.includes, Map keys and Set values use it.

[NaN].includes(NaN)           // true (SameValueZero)
[NaN].indexOf(NaN)            // -1   (===)
new Map([[-0, "a"]]).get(0)   // "a"

When == is fine

x == null checks for null or undefined in one go, and it's a well-known idiom. Use === everywhere else.

07The + operator: add or concatenate?

Binary a + b follows three steps:

  1. Run ToPrimitive on both sides with hint "default".
  2. If either result is a string, convert both to strings and concatenate.
  3. Otherwise convert both to numbers and add. Mixing BigInt and Number throws a TypeError.

The other arithmetic operators (-, *, /, %, **) always convert to numbers. Unary + is ToNumber.

1 + "2"                  // "12"
"3" - 1                  // 2
"3" * "4"                // 12
1 + 2 + "3"              // "33": left to right, 3 + "3"
"1" + 2 + 3              // "123"
"1" + 1 - 1              // 10: "11" - 1
true + true              // 2
null + 1                 // 1: null → 0
undefined + 1            // NaN
"5" + null               // "5null"
[] + []                  // "": "" + ""
[] + {}                  // "[object Object]"
[1, 2] + [3]             // "1,23"
"b" + "a" + +"a" + "a"   // "baNaNa": +"a" is NaN
1 + Symbol()             // TypeError

{} + []

At the start of a statement, {} parses as an empty block, so {} + [] evaluates +[] and gives 0. As an expression, ({} + []) gives "[object Object]". Chrome's console wraps input in parentheses, which is why it shows the string.

Template literals vs +: `${obj}` uses hint "string", while "" + obj uses hint "default". With a custom Symbol.toPrimitive, the two can give different results.

08Shallow copy, deep copy and structuredClone

Assignment never copies: after const b = a, both names point at the same object.

Shallow copy

{...obj}, Object.assign({}, obj), [...arr], arr.slice() and Array.from(arr) create a new top-level container. Nested objects are still shared.

const a = { n: 1, inner: { x: 1 } };
const b = { ...a };
b.n = 2;          // a.n is still 1
b.inner.x = 99;   // a.inner.x is now 99: shared

Spread copies own enumerable properties, including symbol keys. It drops the prototype, so a class instance becomes a plain object, and it invokes getters, so you copy the value rather than the getter.

Deep copy with a JSON round-trip

JSON.parse(JSON.stringify(obj)) works for plain data but is lossy:

InputAfter the round-trip
undefined, function or symbol as an object propertyKey is dropped
The same values inside an arraynull
DateISO string, no longer a Date
Map, Set, RegExp{}
NaN, Infinitynull
-00
BigIntTypeError
Circular referenceTypeError
Class instancePlain object, prototype lost

Deep copy with structuredClone

  • Handles circular references, Date, RegExp, Map, Set, ArrayBuffers and typed arrays, BigInt and Error types.
  • Throws a DataCloneError on functions, symbols and DOM nodes.
  • Still loses the prototype (class instances become plain objects), getters and setters (the value is copied) and property descriptors.

React Native

Don't assume structuredClone exists in your JavaScript runtime. Check it before relying on it, and fall back to a library such as lodash's cloneDeep.

In React state you rarely deep copy

Copy only the path you change. This is called structural sharing:

setUser(u => ({ ...u, address: { ...u.address, city: "Pune" } }));

Unchanged branches keep their references, so memoised children skip re-rendering. Redux Toolkit does this for you through Immer.

RecapInterview cheat sheet

One-line answers to the questions that come up most.

What is typeof null?
"object". A type-tag bug from version one that was never fixed because fixing it would break the web.
What is typeof NaN?
"number".
What is typeof class {}?
"function".
null vs undefined?
undefined is the engine's default: unassigned variables, missing properties, functions with no return. null is an intentional "empty" set by a developer. Number(null) is 0 and Number(undefined) is NaN. JSON keeps null and drops undefined properties. Default parameters trigger only on undefined, not null.
Is JavaScript pass by reference?
No. It is pass by value, and for objects the value is a reference (call by sharing).
Why is 0.1 + 0.2 !== 0.3?
IEEE-754 binary floats can't represent 0.1 exactly. Compare with an epsilon or work in integers.
What is the max safe integer?
2^53 - 1, because a double has 53 bits of precision.
How do you check for NaN?
Number.isNaN, not the global isNaN, which coerces.
== vs ===?
== coerces through the IsLooselyEqual algorithm; === never coerces. Use ===, except for x == null.
Object.is vs ===?
They differ only on NaN (equal under Object.is) and ±0 (not equal under Object.is). React uses Object.is.
Why is [] == ![] true?
Walk the four steps in section 06: boolean to number, array to "", string to number, then 0 == 0.
What is [] + {}?
"[object Object]".
Why does ["1","2","3"].map(parseInt) give [1, NaN, NaN]?
map passes the index, which parseInt reads as the radix.
Why is null >= 0 true but null == 0 false?
Relational operators use ToNumber, which turns null into 0. == has its own null rule.
List the falsy values.
Eight of them: false, 0, -0, 0n, "", null, undefined, NaN.
How does an object become a primitive?
Symbol.toPrimitive if present; otherwise valueOf and toString, in an order set by the hint.
How do you deep clone?
structuredClone. A JSON round-trip loses Dates, Maps, undefined and functions, and throws on circular references and BigInt.
What is autoboxing?
A primitive is temporarily wrapped in its wrapper object so a property can be looked up.
Is typeof x === "object" enough to detect objects?
No. null passes the check and functions fail it.
